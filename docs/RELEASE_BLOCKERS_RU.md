# Блокеры коммерческого релиза ПОТОК CRM

Статус на Pilot v0.14: **НЕ ГОТОВ К PRODUCTION**.

## Подтверждено локально
- 151 выбранный тест проходит в штатном QA runner (42 файла; PostgreSQL-интеграция исключена по условиям среды).
- 122 Python-файла проходят compileall и AST-аудит.
- Статический аудит структуры миграций: 27 ревизий, один корень, нет ветвления.
- Версия API: 0.14.0-pilot; баннер интерфейса синхронизирован с 0.14.
- Проверка Compose YAML и shell-скриптов может выполняться локально; это не запуск контейнеров.

## Блокеры
1. PostgreSQL integration: установить psycopg, поднять только disposable test DB, прогнать Alembic с нуля и upgrade path, выполнить RLS/least-privilege/audit tests. Не использовать рабочую БД.
2. Frontend reproducibility: отсутствует `frontend/package-lock.json`; `npm ci` невозможен. Создать lockfile в среде с доступом к npm registry, зафиксировать зависимости, выполнить `npm ci` и `npm run build`. JSX syntax error in `App.tsx` was fixed; global `tsc` now proceeds to missing-module/type errors because React/Vite packages are not installed.
3. Docker build/runtime: Docker CLI/daemon недоступны в текущей среде; проверить сборку API и frontend images, healthchecks, volumes, network и shutdown.
4. Auth: реализованы HttpOnly SameSite cookies, Secure в production, CSRF double-submit, Origin allowlist и logout. Реализованы серверный реестр сессий, проверка активной сессии при каждом cookie-запросе, отзыв отдельной сессии и завершение всех сессий пользователя. Добавлены список устройств/сеансов и отзыв выбранного сеанса. Не реализованы продление/ротация refresh-сессий; нужны E2E/penetration tests, проверка CORS и reverse proxy.
5. Tenant isolation: дополнить реальными PostgreSQL tests по всем tenant-owned сущностям и связям, включая cross-tenant IDs, documents/downloads, shipments, finance, approvals.
6. Backup/restore: проверить зашифрованные резервные копии БД и файлов, retention, восстановление и RPO/RTO.
7. Operational readiness: российский production hosting, TLS, мониторинг, алерты, ротация секретов, обновления и план отката. Не разворачивать до готового релиза и отдельного согласования.
8. Legal/compliance: провести юридическую проверку российского режима персональных данных, локализации, договоров обработки, политики хранения и удаления.
9. Functional acceptance: закончить реальные экраны/потоки тендеров, заказов, закупок, склада, финансов, согласований и документов; демо-KPI заменить только данными подтверждённых операций.

## Запреты до закрытия блокеров
- Не называть сборку коммерческим релизом.
- Не подключать реальные клиентские данные.
- Не утверждать, что PostgreSQL RLS, frontend production build или Docker runtime проверены, пока нет соответствующих логов успешного запуска.
- Не размещать данные российских клиентов на немецком сервере.
