# Склад: приёмка и партии — Core 2.0

## Реализовано
- Приёмка только по согласованной закупке (`authorized`).
- Частичная приёмка отдельных строк заказа.
- В каждой строке фактическое количество разделяется на принятое и брак; сумма должна совпадать.
- Принятое годное количество создаёт отдельную партию с закупочной ценой, единицей измерения, местом хранения и остатком.
- Брак фиксируется отдельно и не увеличивает складской остаток.
- Повторная приёмка ограничена неотгруженным/непринятым остатком заказа по сумме ранее зарегистрированных приёмок.
- Доступ к приёмке: директор и кладовщик. Просмотр партий и приёмок: директор, кладовщик, закупщик, бухгалтерия.
- Tenant RLS, составные внешние ключи same-company, аудит приёмки.

## API
- `POST /api/v1/warehouse/receipts` — зарегистрировать приёмку.
- `GET /api/v1/warehouse/receipts` — список приёмок.
- `GET /api/v1/warehouse/batches?search=...` — список партий и доступных остатков.

## Ограничения текущей версии
- Нет списания, перемещения, резервирования и отгрузки; остаток партии пока равен принятому количеству.
- Нет отдельного карантинного статуса и процедуры возврата/утилизации брака.
- Нет загрузки первичных документов, OCR и сверки с УПД.
- Не выполнены PostgreSQL migration/RLS integration tests в этой среде.
- Создание приёмки записывает факт, но не закрывает закупку и не проводит платёж.
