# Дебиторская и кредиторская задолженность v2.8

## Модель
- `receivable` — обязательство заказчика перед компанией.
- `payable` — обязательство компании перед поставщиком.
- Обязательство содержит номер, сумму RUB, контрагента, срок оплаты и необязательную ссылку на закупочный заказ.
- `finance_allocations` распределяет подтверждённое денежное движение на одно обязательство.

## API
- `POST /api/v1/finance/obligations`
- `GET /api/v1/finance/obligations?side=receivable|payable`
- `POST /api/v1/finance/obligations/{id}/allocations`
- `GET /api/v1/finance/obligations/summary`

## Контроль
1. Только директор и бухгалтер.
2. Только данные активной компании; `company_id` от клиента не принимается.
3. Дебиторская задолженность уменьшается только подтверждённым `receipt`.
4. Кредиторская задолженность уменьшается только подтверждённым `payment`.
5. Нельзя распределить больше остатка обязательства или движения.
6. Создание и распределение фиксируются в аудите.
7. Сводка отдельно показывает общие суммы, остатки и просроченные остатки.

## Ограничения
Нет автоматического формирования обязательств из продажных заказов/договоров, полноценного справочника контрагентов, отмены/сторно распределений, банковской сверки и налогового учёта. Требуются PostgreSQL integration tests, в том числе конкурентные попытки распределить одну сумму.
