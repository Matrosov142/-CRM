# ПОТОК CRM Pilot v0.23 — журнал изменений

## Связь запроса предложений с позицией тендера

- Строка запроса коммерческого предложения может быть связана с конкретной позицией тендера.
- Связь необязательная для совместимости с ранее созданными RFQ.
- При указании связи обязательны оба идентификатора: тендер и позиция.
- API проверяет, что позиция принадлежит указанному тендеру и текущей компании.
- В деталях RFQ возвращаются идентификаторы исходного тендера и позиции.
- PostgreSQL composite FK ссылается на составной ключ позиции и запрещает межкомпанейские связи; удаление используемой позиции запрещено.
- Внешняя отправка запросов не добавлена: RFQ остаётся подготовленным до отдельного подтверждённого процесса отправки.

## Ограничения проверки

- Локальные unit/static tests не заменяют запуск миграции 0031 на PostgreSQL.
- PostgreSQL/RLS runtime, production-сборка React, browser E2E и Docker runtime в текущей среде не выполнены.

## Дополнительная проверка целостности ORM-моделей

- Обнаружено, что таблицы `processing_jobs`, `processing_operations` и `processing_materials` присутствовали в исторических миграциях, но отсутствовали в общем SQLAlchemy metadata.
- Добавлены ORM-модели, согласованные с миграцией 0017 и используемыми составными tenant-FK.
- Это исправляет неполноту metadata для инструментов, использующих `Base.metadata`, включая создание тестовой схемы и анализ миграций.
- SQLite `Base.metadata.create_all()` успешно создал 43 таблицы. Это проверка согласованности ORM metadata, не замена PostgreSQL миграций/RLS.
