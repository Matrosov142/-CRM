# Связь доставки с отгрузкой — Pilot 0.7

## Что добавлено
- При подтверждении отгрузки можно указать `delivery_estimate_id`.
- Привязка разрешена только к расчёту доставки текущей компании.
- К отгрузке привязывается выбранный вариант расчёта; вариант должен быть предварительно выбран вручную.
- Плановая стоимость фиксируется в `planned_delivery_cost` на момент создания отгрузки и не меняется при последующем изменении исходного расчёта.
- Фактическая стоимость записывается отдельным действием `POST /api/v1/warehouse/shipments/{shipment_id}/actual-delivery-cost`.
- Ответ содержит отклонение факта от плана. Повторная корректировка факта допускается и отражается в аудите.
- Список отгрузок возвращает ссылку на расчёт, плановую и фактическую стоимость.

## Контракты
При создании отгрузки (`POST /api/v1/warehouse/shipments`) новое необязательное поле:
`delivery_estimate_id: UUID | null`.

Запись факта:
```json
{
  "actual_cost": "12500.00",
  "delivered_at": "2026-11-08T12:00:00Z",
  "note": "Счёт перевозчика №..."
}
```

Доступ к записи факта: директор, логистика, бухгалтерия. Проверки компании выполняются на сервере; FK составной `(company_id, delivery_estimate_id)` защищает от межкомпанейской привязки. Удаление связанного расчёта ограничено.

## Ограничения
- Тарифы и расстояние по-прежнему вводятся вручную; автоматического запроса тарифов, заказа перевозки, GPS/маршрутизации и диспетчеризации нет.
- Существующие отгрузки остаются без расчёта доставки; миграция не создаёт фиктивных связей.
- Фактическая стоимость — введённая пользователем сумма, а не подтверждённый банковский платёж.
- Миграция требует проверки и применения на PostgreSQL перед пилотом.
