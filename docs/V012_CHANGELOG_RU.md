# ПОТОК CRM Pilot v0.12 — журнал изменений

## Серверные браузерные сессии

- Добавлена таблица `auth_sessions` и миграция `0025_auth_sessions`.
- Каждая браузерная cookie-сессия получает уникальный `jti`, который хранится на сервере.
- Каждый запрос с cookie проверяет существование, владельца, компанию, срок действия и отсутствие отзыва сессии.
- Выход отзывает текущую сессию на сервере, а не только удаляет cookie.
- Добавлен `POST /api/v1/auth/session/logout-all` для отзыва всех активных браузерных сессий пользователя.
- Bearer API-токены сохранены для совместимости; они не являются браузерными cookie-сессиями и не попадают в реестр `auth_sessions`.

## Безопасность и ограничения

- Таблица `auth_sessions` используется до установки tenant-контекста; запрос к ней ограничивается `jti`, `user_id` и `company_id` из проверенного JWT. Она не содержит бизнес-данных компании.
- Не реализованы продление сессии, список устройств и отдельное управление сессиями по устройствам.
- Необходимо провести PostgreSQL-проверку миграции и поведения отзыва в реальной тестовой БД.
- Необходимо провести внешний security review, включая хранение сессий, rate limiting, password reset и настройки cookie за reverse proxy.

## QA

- Python compileall и статический аудит выполняются локально.
- PostgreSQL integration, frontend production build и Docker runtime требуют соответствующих сред и не считаются пройденными без фактического запуска.
