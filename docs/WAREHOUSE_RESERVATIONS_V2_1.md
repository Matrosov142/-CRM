# Складские резервы — Core v2.1

## Правила
- Резерв не меняет физический остаток партии.
- Доступно = физический остаток − сумма активных резервов.
- Резерв создаётся только в пределах доступного количества.
- Повторное резервирование той же партии в одном запросе запрещено.
- Освобождение требует причины; повторное освобождение блокируется.
- Все операции ограничены company_id и RLS, пишутся в аудит.
- Отгрузка и списание не выполняются этим модулем.

## API
- `POST /api/v1/warehouse/reservations` — создать резерв.
- `POST /api/v1/warehouse/reservations/{id}/release` — освободить весь резерв.
- `GET /api/v1/warehouse/availability` — физический, зарезервированный и доступный остаток по партиям.

## Ограничения текущей версии
Освобождение пока целиком, без частичного освобождения. Нет автоматической привязки к заказу: `reference` — обязательная текстовая ссылка, например номер заказа. Частичная отгрузка будет отдельным модулем и должна потреблять конкретные партии/резервы транзакционно.

Перед эксплуатацией необходимы PostgreSQL-интеграционные тесты конкурентного резервирования, RLS и проверки прав на реальной БД.

## Проверки сборки
Python syntax compilation and offline structural checks are required before packaging. A full test run requires the PostgreSQL driver and a configured PostgreSQL test database.
