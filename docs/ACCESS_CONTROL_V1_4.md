# Контроль лимитов и согласований — v1.4

## Денежная точность
API использует Decimal для `limit_amount` и `amount`, до двух десятичных знаков и максимум 14 цифр. Значения с тремя знаками после запятой отклоняются валидацией.

## Запрос сотрудника
`POST /api/v1/access/approval-requests` создаёт запрос, если лимит установлен и сумма выше него. Повторный идентичный запрос со статусом `pending` отклоняется. `GET /api/v1/access/my-approval-requests` возвращает запросы текущего сотрудника и статус решения.

## Просмотр директором
`GET /api/v1/access/approval-requests` показывает запросы компании, включая решение и время решения. `POST /api/v1/access/approval-requests/{request_id}/decision` фиксирует решение.

## Обязательное подключение
Любой реальный обработчик операции `purchase`, `supplier_advance`, `payment` или `warehouse_write_off` должен вызывать `require_operation_authorization` в той же транзакции, что и изменение бизнес-данных, и коммитить их вместе. Нельзя создавать отдельный commit после потребления согласования до записи бизнес-операции. При ошибке операция и потребление должны откатываться вместе.

## Ограничения проверки
Unit-тесты точности Decimal прошли (3). Статический QA и AST прошли. Полный pytest не запустился из-за отсутствующего драйвера `psycopg`; PostgreSQL RLS и конкурентное потребление не проверены. До production необходимы PostgreSQL integration tests, проверка миграций на чистой БД и review runtime DB grants.
