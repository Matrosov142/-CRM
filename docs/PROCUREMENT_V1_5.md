# Закупки — Core v1.5

## Реализовано
- Создание черновика заказа поставщику с 1–100 позициями.
- Поля: номер, поставщик, ИНН (10 или 12 цифр), наименование, количество, единица, цена.
- Серверный расчёт суммы каждой строки и итога; RUB only; денежная точность Decimal.
- Список заказов, фильтр по статусу, просмотр карточки.
- Внутреннее подтверждение закупки с проверкой лимита `purchase`.
- Если сумма выше лимита, необходим `approval_request_id` со статусом approved, созданный тем же сотрудником для той же компании и операции, с точным совпадением суммы.
- Согласование используется один раз; потребление, смена статуса заказа и аудит коммитятся одной транзакцией.
- Tenant RLS на заказах и позициях. Составные FK гарантируют, что позиция, заказ, создавший/подтвердивший сотрудник и согласование принадлежат одной компании.

## API
- `POST /api/v1/procurement/orders` — создать черновик.
- `GET /api/v1/procurement/orders` — список (до 200 последних), фильтр `status`.
- `GET /api/v1/procurement/orders/{order_id}` — карточка с позициями.
- `POST /api/v1/procurement/orders/{order_id}/authorize` — подтвердить закупку внутри CRM; тело может содержать `approval_request_id`.

## Граница функциональности
`authorized` — внутреннее подтверждение, не отправка поставщику и не доказательство заключения договора. Не реализованы реальная отправка заказа, карточки поставщиков, RFQ, ответы, договоры, связь с тендером/заказом клиента, платежи, приёмка и склад.
