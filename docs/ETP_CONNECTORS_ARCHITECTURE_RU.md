# Интеграции с электронными торговыми площадками — архитектура ПОТОК CRM

## Текущий статус

В релизе добавлен только справочник площадок и read-only API их статуса. Ни одна площадка не подключена. Наличие API, право его использования и доступность данных для аккаунта не подтверждены. Нельзя называть синхронизацию работающей.

## Очерёдность

1. B2B-Center — первая интеграция.
2. РТС-тендер.
3. Фабрикант.
4. Сбер А.
5. ТЭК-Торг.

## Целевой контракт адаптера

Каждый адаптер реализует независимый интерфейс: `validate_credentials`, `capabilities`, `list_tenders`, `get_tender`, `list_documents`, `get_document`, `get_status`, `healthcheck`. Реализация допускается только на основании официальной документации и разрешённых условий площадки.

## Требования к эксплуатации

- OAuth/API-токены или иной официальный способ авторизации; секреты только в защищённом хранилище, шифрование при хранении и маскирование в логах.
- Пароли пользователей площадок не запрашивать и не сохранять в открытом виде.
- Раздельные подключения для каждой компании ПОТОК CRM; серверная проверка tenant_id на каждом запросе.
- Журнал синхронизации: площадка, компания, операция, внешний ID, время, результат, код ошибки, число повторов; без секретов и лишних персональных данных.
- Идемпотентная загрузка по внешнему ID + площадка + tenant; дедупликация вложений по контрольной сумме.
- Ограничение частоты, backoff, очередь повторов, ручной повтор и отключение подключения.
- Сохранение оригиналов документов и истории версий; извлечённые данные не перезаписывают оригинал.
- Ручной импорт PDF/XLSX/DOCX/ZIP остаётся резервным каналом.
- Не выполнять автоматическую подачу заявок, подписание, ценовые предложения, переторжку или иные юридически значимые действия. Только подготовка и напоминания; отправка — после явного подтверждения сотрудника.

## Этапы приёмки каждого адаптера

1. Проверить публичную документацию, договор/тариф и разрешённые сценарии.
2. Подтвердить тестовый доступ и отдельные технические учётные данные.
3. Реализовать только заявленные площадкой методы.
4. Проверить импорт, обновление, дедупликацию, удаление/отзыв доступа, ошибки и повторные запросы.
5. Проверить изоляцию двух тестовых компаний.
6. Провести пользовательскую приёмку на тестовых тендерах.
7. Только после этого отметить адаптер как активный.
