# ПОТОК CRM Core v3.4 — QA и статус допуска

## Что изменено

- Версия FastAPI синхронизирована с `3.4.0`.
- Добавлен `tools/qa_release.py` для повторяемой локальной проверки.
- Добавлен машиночитаемый отчёт `docs/QA_REPORT_V3_4.json`.
- Сохранены все прежние модули; новых бизнес-функций в этой версии нет.

## Проверки в текущем окружении

- Статический аудит: 94 Python-файла, 22 миграции, один корень, без ветвления.
- `compileall`: успешно.
- Автономный набор: 100 тестов пройдены.
- Полный `pytest`: не прошёл сбор тестов из-за `ModuleNotFoundError: No module named 'psycopg'` при импорте `app.database` в `tests/test_operation_controls.py`.
- `tests/test_postgres_rls_integration.py`: пропущен тестовым окружением из-за отсутствия зависимостей PostgreSQL.

## Что эти результаты НЕ доказывают

Офлайн-тесты не доказывают работоспособность PostgreSQL, корректность миграций на реальном сервере, безопасность RLS, изоляцию арендаторов на уровне БД, устойчивость к конкурентным транзакциям или production-безопасность.

## Блокирующие проверки до пилота

1. Установить зависимости из `requirements.txt` в чистом виртуальном окружении.
2. Поднять отдельную тестовую PostgreSQL, применить все миграции с нуля и проверить downgrade/restore.
3. Запустить полный pytest, включая `test_operation_controls.py` и `test_postgres_rls_integration.py`.
4. Пройти негативные тесты tenant isolation и RBAC по каждому изменяющему API.
5. Проверить гонки резервирования, отгрузки, распределения платежей и версий документов.
6. Перевести авторизацию с `localStorage` на защищённую серверную сессию (`HttpOnly`, `Secure`, `SameSite`) с CSRF-защитой, отзывом и ротацией.
7. Реализовать MFA, rate limiting, восстановление доступа и мониторинг.
8. Проверить MIME по содержимому, потоковые лимиты, антивирусную проверку, атомарность DB/файловых операций и backup/restore.
9. Убрать демонстрационные KPI из рабочего режима и завершить реальные экраны модулей.
10. Провести независимый security review и юридическую проверку требований 152-ФЗ.

## Решение

**Статус: инженерная сборка, не готова к пилоту с реальными данными.** Следующий приоритет — интеграционная PostgreSQL-среда и закрытие блокирующих проверок, а не добавление новых модулей.
