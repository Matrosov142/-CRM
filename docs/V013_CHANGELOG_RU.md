# ПОТОК CRM Pilot v0.13 — защита входа

## Что добавлено

- Единый механизм ограничения неудачных попыток для bearer- и cookie-входа.
- Порог: 8 неудачных попыток на нормализованный email или 30 на IP за скользящие 15 минут.
- При достижении порога API возвращает HTTP 429 и `Retry-After: 900`.
- События неуспешного входа хранятся в PostgreSQL; email и IP не сохраняются открытым текстом — используются HMAC-SHA256 отпечатки с ключом приложения.
- IP берётся только из `request.client.host`. Заголовок `X-Forwarded-For` не доверяется без отдельной конфигурации доверенного прокси.
- Добавлена миграция `0026_login_failure_throttle`.

## Ограничения и безопасность

- Таблица `login_failures` — глобальная/pre-tenant, поскольку защита работает до аутентификации и выбора компании.
- В production требуется проверить доступ к этой таблице под runtime-ролью PostgreSQL и настроить очистку записей старше 48 часов.
- Пороги являются стартовыми и требуют настройки после пилотной эксплуатации, чтобы избежать блокировки общих IP офисов.
- Это дополнительная защита, а не замена MFA, мониторингу, проверке паролей на утечки и полноценному тестированию безопасности.
- Если приложение находится за reverse proxy, `request.client.host` должен быть проверен на реальное поведение развёртывания; нельзя включать доверие к forwarded headers для произвольных источников.

## Проверки

Новые unit-тесты проверяют пороги, HTTP 429/Retry-After, нормализацию и HMAC-отпечатки, а также отказ доверять `X-Forwarded-For`. PostgreSQL integration, frontend production build и Docker runtime остаются отдельными блокерами.
