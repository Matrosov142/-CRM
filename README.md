# ПОТОК CRM — технический пилот 0.25

Это первый развёртываемый закрытый пилотный комплект: PostgreSQL 16 + FastAPI + React/nginx, отдельные роли владельца схемы и runtime-пользователя, локальный web bind, health/readiness checks, одноразовое создание первого директора и резервное копирование.

**Не production-ready. Не загружайте реальные персональные или финансовые данные.**

PostgreSQL разделён на `potok_admin` (одноразовый bootstrap), `potok_owner` (одноразовые миграции) и `potok_runtime` (API). Работающий API не получает пароли администратора БД или владельца схемы.

Инструкция: [`docs/PILOT_RUNBOOK_RU.md`](docs/PILOT_RUNBOOK_RU.md)

Запуск на Linux с Docker Compose v2:

```bash
bash ops/pilot-up.sh
```

Проверка:

```bash
curl -fsS http://127.0.0.1:18080/api/v1/health/ready
```

Первый директор: используйте одноразовую команду из раздела «Создание первого директора» в `docs/PILOT_RUNBOOK_RU.md`. Пароль администратора БД передаётся отдельному временному контейнеру, а не API.

Резервная копия:

```bash
bash ops/backup-pilot.sh
```

Подробные ограничения и критерии допуска см. в runbook и [`docs/RELEASE_BLOCKERS_RU.md`](docs/RELEASE_BLOCKERS_RU.md).

## Расчёт доставки (Pilot 0.4)

API `POST /api/v1/transport/estimate` сравнивает введённые тарифы транспортных компаний с расчётом собственного транспорта. Требуются адреса отправления/назначения, вручную подтверждённое расстояние в одну сторону, описание груза и хотя бы один вариант доставки. Для перевозчика можно передать фактическое коммерческое предложение (`quoted_total`) либо тариф: подача + ставка за км + погрузка + разгрузка + платные дороги + страхование + дополнительные расходы. Для собственного транспорта учитываются расход топлива, цена топлива, водитель, амортизация, обслуживание, платные дороги и погрузочно-разгрузочные расходы; по умолчанию учитывается обратный путь.

Доступ: директор, логист, менеджер закупок. Все суммы в RUB. Результат — оценка для сравнения, не заказ перевозки. Геомаршрут, пробки, тарифы перевозчиков, ограничения по габаритам/весу и доступность машин автоматически пока не запрашиваются. Перед выбором подтвердить коммерческое предложение и сроки у перевозчика. Автоматического бронирования/диспетчеризации нет.


## Интерфейс расчёта доставки — Pilot 0.5

В русскоязычном интерфейсе после входа доступен раздел «Расчёт доставки». Форма отправляет данные в `POST /api/v1/transport/estimate` и отображает сравнение тарифа перевозчика с собственным транспортом. Для перевозчика можно внести цену из коммерческого предложения. Параметры собственного транспорта включают топливо, водителя, амортизацию и обслуживание. Раздел доступен пользователю с ролью директора, логиста или менеджера закупок. Показатели главной панели по-прежнему демонстрационные.


## Сохранение расчётов — Pilot 0.6

Расчёт доставки сохраняется в PostgreSQL в таблице `delivery_estimates`, с tenant RLS, составом вариантов, автором и временем. `GET /api/v1/transport/estimates` возвращает историю компании. `POST /api/v1/transport/estimates/{id}/select?option_index=N` сохраняет ручной выбор логиста/директора и пишет событие в аудит. В интерфейсе доступны просмотр истории и выбор варианта. Выбор не является заказом перевозки.


## Pilot 0.6 — сохранение доставки

Добавлена миграция `0023_delivery_estimates`. Расчёты доставки сохраняются в PostgreSQL с RLS по компании. Доступны история расчётов и сохранение выбранного способа доставки; действия журналируются. Для применения обновления на уже развёрнутой базе необходимо выполнить штатные миграции Alembic из релизного runbook. В текущем проекте релиз ещё не развёрнут.


## Pilot 0.7 — связь доставки с отгрузками

Добавлена привязка выбранного расчёта доставки к отгрузке, фиксация плановой стоимости и отдельная запись фактических затрат с расчётом отклонения. Подробности: `docs/TRANSPORT_SHIPMENT_LINK_V0_7_RU.md`.


## Pilot 0.8 — безопасность интерфейса и отгрузки

Bearer-токен хранится только в памяти приложения; после обновления страницы требуется повторный вход. Добавлен интерфейс отгрузок с плановой и фактической стоимостью доставки и отклонением. Это промежуточная мера: HttpOnly Secure cookie sessions и CSRF ещё не реализованы.

## Pilot 0.9 — усиление QA и RLS-проверок

Штатный QA runner запускает unit-тесты контролей операций без необходимости в PostgreSQL DBAPI driver, используя SQLite URL только для инициализации SQLAlchemy. 133 теста прошли в 38 файлах. PostgreSQL RLS integration остаётся отдельной проверкой и в этой среде не выполнялась. JSX-синтаксическая ошибка исправлена, но полная проверка типов и сборка frontend не подтверждены: package-lock отсутствует, npm registry недоступен; Docker runtime также не запускался. См. [`docs/V09_CHANGELOG.md`](docs/V09_CHANGELOG.md), [`docs/QA_REPORT_PILOT_0_9.json`](docs/QA_REPORT_PILOT_0_9.json) и [`docs/RELEASE_BLOCKERS_RU.md`](docs/RELEASE_BLOCKERS_RU.md).

## Управление браузерными сеансами (v0.14)

В разделе «Безопасность» пользователь видит активные браузерные сеансы и может завершить отдельный сеанс. Список ограничен текущим пользователем; JWT и refresh-секреты не выдаются клиенту. Метаданные браузера хранятся ограниченно (до 500 символов) и используются только для ориентировочного определения типа устройства.


## Pilot 0.17
Реестр тендеров: ручное создание и просмотр через API, изоляция по компании, защита CSRF для изменений. См. `docs/V017_CHANGELOG_RU.md`. Production-сборка frontend и PostgreSQL runtime пока требуют отдельного запуска.

## Pilot 0.18 — позиции тендера
Карточка тендера теперь позволяет просматривать и добавлять позиции закупки. Для каждой позиции сохраняются наименование, характеристики, количество, единица измерения, ориентировочная цена и примечание. Предварительная сумма является оценкой, а не подтверждённой себестоимостью. Backend API поддерживает просмотр, создание, изменение и удаление позиций с tenant-scoping, аудитом и PostgreSQL RLS. См. `docs/V018_CHANGELOG_RU.md`.

## Pilot 0.19 — предварительная калькуляция тендерной позиции
Добавлен калькулятор себестоимости на единицу: закупка, логистика, обработка, упаковка, налоги/сборы и прочие расходы. Формируются осторожный, целевой и агрессивный сценарии на основе заданной маржи. Маржа — доля цены продажи. Все расчёты предварительные; налог/НДС вводится явно, автоматически не выводится. Результат не сохраняется и не заменяет подтверждённую себестоимость. См. `docs/V019_CHANGELOG_RU.md`.

## Pilot 0.20 — история версий калькуляции тендерной позиции
- Предварительный расчёт теперь можно сохранить как отдельную неизменяемую версию с автором, временем, входными допущениями и рассчитанными сценариями.
- История доступна только участникам той же компании; таблица защищена FORCE RLS и составными внешними ключами.
- Сохранение требует роли директора или тендерного специалиста; просмотр доступен разрешённым ролям тендерного процесса.
- Изменение исходных допущений создаёт новую версию, старые записи не перезаписываются.
