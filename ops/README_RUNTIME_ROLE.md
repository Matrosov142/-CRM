# Роли PostgreSQL ПОТОК CRM

В PostgreSQL используются три раздельные роли:

- `potok_admin` — административная роль PostgreSQL. Используется только короткоживущим `db-bootstrap` job для первичной настройки ролей и одноразовой командой создания первого директора. Не передаётся в API container.
- `potok_owner` — владелец схемы и объектов. Не SUPERUSER, не BYPASSRLS. Credential доступен только короткоживущему `db-migrate` job.
- `potok_runtime` — роль FastAPI. Не владеет таблицами, не SUPERUSER, не BYPASSRLS; получает только DML-права, а для `audit_events` — только SELECT/INSERT.

## Важные правила

- Пароли генерируются отдельно, хранятся только в `.env.pilot` с правами `0600`.
- API подключается к БД только через `DATABASE_URL` с `potok_runtime`; контейнер API не получает admin/owner пароли.
- Миграции подключаются через `MIGRATION_DATABASE_URL` с `potok_owner`.
- `potok_admin` не должен попадать в URL приложения, логи или переменные окружения пользовательского frontend.
- Для старых пилотных volumes, где `potok_owner` был первоначальным суперпользователем, `db-bootstrap` выполняет одноразовое создание `potok_admin` и понижение `potok_owner` до непривилегированной роли. Данные и volume не удаляются.
- Перед обновлением всё равно сделайте backup и проверьте восстановление на отдельной копии.
- Сначала проверяйте на disposable test-БД. Не использовать production без отдельного согласования.
